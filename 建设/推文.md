## #1 匿名集不是 TVL

**配图:`图/01-anonymity-set.png`** · 现在可发

这条是给不认识你的人看的。它对任何关心隐私的人都有用,不需要先关心 Strata 是什么——
所以它是这批里最可能被转发的一条。

```
Your privacy in a mixer is not the TVL.

It's the number of unspent notes at your denomination.

A pool holding ten million dollars with 12 unspent notes gives an observer a 1-in-12 guess. The proof is still perfect. The cover is not.

Most interfaces lead with the ten million.
```

> 写成 `$10M` 会被 X 当作 cashtag 转成蓝色链接,点进去是股票代码搜索页。
> 而且它转得不一致——同一条里前一个不变蓝、后一个变蓝。正文里避开
> `$` + 数字字母的写法;图片里的 `$10,000,000` 是像素,不受影响。

## #2 为什么明知不赚钱还是留在 0.01

**配图:`图/02-relayer-economics.png`** · 现在可发

几乎没人会公开自己的毛利率。这条把它贴出来,并且说明我们选了亏的那个——
因为冷启动期匿名集比收入重要。同样 0.5 ETH 的种子,0.01 面额买到 50 张票据,
0.1 只买到 5 张,而匿名集数的是票据不是金额。

```
Our relayer runs at a 12% margin. Here's why we're keeping it that way.

Measured from five real withdrawals on chain:

withdrawal gas        0.0000176 ETH
relayer fee @ 0.01    0.0000200 ETH  → 12% margin
relayer fee @ 0.1     0.0002000 ETH  → 91% margin

Proof verification costs the same regardless of note size, so a bigger note is pure margin. 76x more, for one config change.

We stayed at 0.01. The anonymity set counts notes, not value — the same seed buys ten times as many of them at the smaller size, and a pool nobody can hide in earns nothing anyway.
```

## #3 那 0.1% 去哪了

现在可发。无配图,或复用 `图/02`。

这条的价值在于它主动说明了一件对你不利的事(0.2% 是你收的),然后给出一个别人验证得了的事实。
先认自己拿钱,再讲不能拿的部分,可信度比反过来高得多。

```
The withdrawal fee is 0.3%, split in the contract and unchangeable:

0.2% → the relayer that fronts your gas. We run the default one, so today that's us. Anyone can run one; your proof names whichever you pick.

0.1% → a pool reserve. There is no function anywhere in the contract that pays it out. Not to me, not to anyone.

No owner. No upgrade. No pause.
```

## #4 换掉了一个弱密钥

现在可发。无配图。

主动交代自己修过的一个真实缺陷。这类帖子的说服力来自"没人逼你说",
而且 README 里的 SHA-256 让人能自己核对新密钥确实换了。

```
Redeployed the pool against a fresh proving key.

The first one was generated with Date.now() + Math.random(). Neither half is acceptable: the timestamp is recoverable from the deployment block, and V8's Math.random is xorshift128+, not a CSPRNG. Whoever reconstructs that seed can forge proofs, and a forged proof is indistinguishable on chain from a real one.

The new key uses crypto.randomBytes(32). The old one is gone.

Still a single-party phase 2 — that is disclosed in the README and it is the next thing to fix. SHA-256 of every artefact is published so you can check which key you're proving against.
```

## #6 "审计了吗"

现在可发。无配图。

所有人都会问这句。主动答比被问了再答强得多,而且每一条都能自己核。
**里面没有一句话超出 README 已经写明的事实**——发之前对一遍 README 的
「What review this code has had」那节。

```
"Is it audited?"

No. Here is exactly what it has had instead.

The withdraw circuit is Tornado Cash v1's, unchanged — only the circom 1 → 2 syntax migration. SHA-256 of every artefact is published, so you can verify that claim instead of believing it.

circomspect, Trail of Bits' static analyser: no errors.

39 tests — 19 on the contracts, 14 in the client, 6 on the relayer. They include the recipient-tampering attack a missing constraint would allow, which is the classic fatal bug in Tornado forks.

A full run on mainnet: 5 deposits, 5 withdrawals to fresh addresses, 1 double-spend correctly rejected.

Groth16 proving now runs in the page against the deployed key, checked against the published verification key. Until today every proof this project had made came out of a Node script.

None of that is an audit. A linter cannot tell you whether a circuit computes the right thing, and the people who wrote the code are the worst people to review it.

Read it before you trust it.
```

## #8 Ceremony 开放

**配图:`图/04-ceremony.png`** · 现在可发 · **这条是目前最重要的一条**

它修的是 README 里坦白的最大缺陷:单人 phase 2。而且因为你把地址字段删了,
「什么都拿不到」反而成了最强的钩子——所有人都见过为空投而做的任务,
没人见过一件明说没有回报的事。

发之前核对过的事实:

- ceremony 已上线,`slotOpen: true`,当前 1 个贡献
- drand round **6362166** = 2026-08-09 17:20 UTC(东京 8/10 02:20),约 14 天后
- `api.drand.sh/public/6362166` 现在返回 `Requested future beacon` ——
  **这个值确实还不存在**,任何人都能自己验

```
Most projects run the trusted setup after launch, if at all. We are running it before the pool opens.

Groth16 needs parameters derived from a secret that has to be destroyed. Whoever can rebuild it can forge proofs and empty the pool. Right now that secret was ours alone to destroy — and our word is not a security model.

The ceremony fixes that. It runs in your browser: 20 MB down, two seconds of work, one upload. Your randomness goes in, then gets thrown away.

Forging against the finished key would need every contributor to have kept their secret. One honest person is enough.

No token, no airdrop, no address collected.

Closes at drand round 6,362,166 — a number that does not exist yet, named in advance so it cannot be shopped for.

stratapool.xyz/#/ceremony
```

> 早前有一版在正文里加了「Two things we are not going to pretend about:」
> 外加两段自我否定。删掉了——**宣告自己诚实本身就是一种表演**,读起来像道歉
> 而不是邀请,而且三段自贬会盖掉唯一的卖点。同一个事实
> (「我们的话不构成安全模型」)留在了正文里,但语气是底气不是忏悔。
>
> 这版也不引用贡献数,所以「匿名贡献可能是同一个人刷的」那个顾虑
> 不需要在推文里解释——README 里写着就够了。

> **一个要想清楚的取舍**:「No airdrop / 不收地址」发出去之后就收不回了。
> 你现在确实没收地址,所以这句是真的;但如果以后发币想奖励贡献者,
> 这条帖子会变成打脸的证据。要留余地的话把那句换成
> 「No allowlist — we do not collect an address.」,陈述事实,不承诺未来。

## #9 仪式即将封存(**时效性极强**)

**配图:`图/05-ceremony-closing.png`** · 只在 round 出块前有效

图里印的是真实终端输出:`curl api.drand.sh/public/6324232` 返回
`Requested future beacon`。**图自己证明自己**——任何人跑一遍同样的命令就能验证
「这个数还不存在」,不需要相信文案。图上那个 latest round 是渲染时的实时值。

drand round **6324232** → 2026-07-27 13:13 UTC。过了这个点这条就作废,直接发 #10。

```
The trusted setup closes in under an hour.

Not at a time we chose — at drand round 6,324,232. That beacon does not exist yet. Nobody can predict it, and once it lands nobody can shop for a different one.

Every contribution so far has folded fresh randomness into the key and thrown it away. Forging a proof against the result would need every single one of those contributors to have kept their secret.

The window is open until the round publishes. It runs in your browser.

stratapool.xyz/#/ceremony
```

> **不写贡献数是刻意的。** transcript 公开,谁都能点进去数。写具体数字会被
> 「这六个是不是同一个人」将军,写「many」这种模糊词去盖一个查得到的数字
> 更糟——那是可以被当场证伪的修辞。「Every contribution so far」两头都站得住。

## #10 仪式已封存(链上核对过)

> **事故记录 · 2026-07-27。** #9 发出去的时候仪式**已经封存了**,而且收官轮
> 不是文案里的 6324232,是 **6324172**。那条帖子三句话全错:
> 「closes in under an hour」「at drand round 6,324,232」「the window is open」。
>
> 原因不是数据当时是假的——写的时候它是真的。是**从写好到发送之间过了一小时,
> 中途仪式被提前收官了,而发送前没有重新拉一次接口**。
>
> **规则:任何带实时数字的帖子,按发送键之前必须重新核一次。**

核对过的事实:

| | |
| --- | --- |
| 收官轮 | **6324172** · 12:43:00 UTC |
| randomness | `a0e170779fea33571e3bf27ed13b118581604948f04eb1bdc0a9eacf0cbb5b42` |
| `slotOpen` | false |
| 新池子 | `0x4daA62B28c4529479785892443E0a0DFe392f460` · 0.01 ETH · solvent |
| 新 verifier | `0x57254c611587343958EAbB70993b85Bc7948524F` |
| zkey | `f2239587…` |

```
The ceremony is closed. Sealed with drand round 6,324,172 — announced before its value existed, so nobody could steer which randomness ended it.

The pool has been redeployed against the result.

You do not have to take our word for which key it runs on. Rebuild it:

curl -so contributed.zkey https://stratapool.xyz/ceremony/zkey
curl -s https://api.drand.sh/public/6324172
snarkjs zkey beacon contributed.zkey final.zkey drand-6324172 a0e170779fea33571e3bf27ed13b118581604948f04eb1bdc0a9eacf0cbb5b42 10

That produces f2239587… — the exact file the deployed verifier was generated from.

Every contributor generated their randomness in their own browser and threw it away. So long as one of them really did, nobody can forge a proof. Including us.
```

**如果 #9 没删**,必须补这一段——否则时间线上并排两个轮次号,看起来像改口:

```
The closing round was brought forward from 6,324,232 once contributions were judged sufficient. Both were in the future when named, which is the only property that matters — but it changed, so it is on the record.
```

> 这条的主角是**可复现**:contributed key 仍在线,配上公开 beacon 就能重算出
> 部署密钥,`f2239587…` 必须对上。绝大多数 ZK 项目做不到——它们的贡献密钥
> 没有留存,只能让你相信最终文件。这比任何形容词都有说服力。

## #12 第一次销毁

**配图:`图/08-token-burn.png`**

```
First burn. 10,000,000 STRATA — 1% of supply — sent to an address whose private key does not exist.

0xdf2a9b31284618e3590c308fd471e3c5b8e48131400bd20640cf624c9afe6727
0xaa13ee71313a3f0bbe5dad826ae1b9c07cc87e7c321f1f50599ddb4a31c85c63

The contract has no mint function and no owner. Check both.
```

链上核对过的事实:

| | |
| --- | --- |
| 销毁量 | **10,000,000**(两笔各 5,000,000) |
| 占比 | 1.00% |
| 去向 | `0x…dEaD` |
| `totalSupply` | 1,000,000,000 · **未变** |
| `mint()` | 字节码中不存在 |
| `owner()` | 字节码中不存在 |

> **三个容易写错的地方:**
>
> 1. 是 **1000 万**不是 100 万。
> 2. `0xdf2a9b31` 是**第一笔**(blk 20853573),`0xaa13ee71` 是第二笔
>    (blk 20854015)。顺序要和浏览器一致。
> 3. 严格说是**锁死**不是销毁——合约没有 `burn()`,`totalSupply` 没变。
>    图上已写明。自己先说,比被人指出来强。
>
> **没有 mint、没有 owner** 这两条对买家的意义比销毁本身大:
> 能增发的话销毁就是演戏,有 owner 的话其他保证都是有条件的。
